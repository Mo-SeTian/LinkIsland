# 链接岛 · 0.2.11

Android 原生测试 App：复制 HTTP / HTTPS 链接，经本地规则匹配，在通知中询问是否打开对应 App 或默认浏览器。包含小米超级岛协议字段，**是否真正上岛需要 HyperOS 实机验证**。

**0.2.4 已撤回，请勿继续安装或使用。** 其新增的 `textButton` 模板会在部分小米 SystemUI 上触发空指针崩溃和重复重启。0.2.5 撤回这套模板，恢复 0.2.3 的 baseInfo / actions 通知结构，保留应用图标和 Root 剪贴板修复。

## 安装与测试

从 GitHub Actions 构建产物或 Message 频道下载 APK。Debug 包名为 `dev.linkisland.app.debug`，Release 包名为 `dev.linkisland.app`，两者可以同时安装。更新后重新点击“开启监听”。

从 0.2.9 及更早的本地测试包迁移时，Release 使用新的项目签名，无法直接覆盖旧测试包，需要先卸载旧版；卸载会清除旧版规则和设置，请提前记录。Debug 可独立安装，保留旧版供对照。此后同一变体使用固定项目签名，可以覆盖升级。

如果 0.2.4 导致系统界面重复重启，已允许 USB 调试时先运行 `adb shell am force-stop dev.linkisland.app`，撤掉链接岛通知并停止监听，然后覆盖安装最新版。无需清除应用数据。

1. 首页中央电源按钮用于开启 / 关闭监听；Shizuku / Root 授权方式在右上角“设置与诊断”中切换，监听开启时需先关闭监听。
2. “匹配规则”进入二级列表，可添加、编辑、停用或删除规则；列表不在首页展开。
3. “链接测试”进入独立测试页；右上角设置图标进入“设置与诊断”。
4. “设置与诊断 → 授权管理”查看各项权限，点按项目进入授权或系统设置，返回后刷新状态。
5. “设置与诊断 → 网页浏览器”选择已安装浏览器、跟随系统默认或每次询问。此选择只影响链接岛，不更改手机的默认浏览器。

后台复制测试：

1. 允许通知权限；在系统通知设置里开启“链接跳转提示”的悬浮通知。
2. 进入“链接测试”，点“发送测试提示”。不必授予 Shizuku / Root，即可单独测试通知和跳转。
3. 打开提示：安装了 GitHub 官方 App 时尝试打开对应仓库；无法处理时会询问是否改用浏览器。
4. 在“设置与诊断”中选择 Shizuku 或 Root，返回首页点击中央电源按钮“开启监听”。
   - **Shizuku**：先安装并启动 Shizuku，然后允许链接岛授权。免 Root 启动通常使用无线调试。重启后需要重新启动 Shizuku。
   - **Root**：需要已 Root 的手机和可用 `su`，在 Root 管理器中授权本 App。不需要同时启动 Shizuku。
5. 返回其他 App，复制一个新的仓库链接，例如 `https://github.com/RikkaApps/Shizuku`。
6. 等待约 2 秒，观察超级岛或通知栏，点击“打开”或“忽略”。提示 30 秒后消失。
7. 复制普通网址，例如 `https://example.org`，验证默认浏览器。
8. 再点首页中央电源按钮关闭监听，会解绑权限服务、停止定时检查并撤销跳转提示。常驻通知也有停止按钮。自动恢复开启时，划掉任务后继续后台监听；关闭自动恢复时，划掉任务会停止监听。两种情况下都会撤销当前跳转提示。仅返回桌面或切换 App 则继续监听。

在 HyperOS 中，若后台监听被系统结束，可在系统应用设置允许自启动、调整电池限制后重试。本版不在开机后自动启动；“监听自动恢复”用于恢复已手动开启的监听及重连授权桥。

## 0.2.11 小红书短链与后台占用

- 小红书已安装但不能直接处理 `https://xhslink.cn` / `https://xhslink.com` 时，点击后才联网读取 HTTPS 重定向，将真实页面交给小红书；保留完整签名参数，不请求笔记正文。若笔记 HTTPS 链接仍不被支持，尝试官方 `xhsdiscover://item/笔记ID`，之后仍可回退浏览器。
- 解析只允许指定小红书域名，最多四次跳转，设置连接、读取超时和总时间预算；无网络或解析失败时说明原因，不反复尝试。自定义规则、其他链接及目标未安装的情况不触发这项联网解析。
- 两秒诊断计数改为内存更新，仅界面在前台时刷新，不再周期写入配置文件或在后台驱动诊断界面刷新。剪贴板事件与两秒兜底检查保留。
- 小米 10 / Android 15 的 120 秒后台 Root 采样中，两进程合计 CPU 约为单核 0.25%，合计 PSS 约 132 MiB；配置文件全程没有变化。本次没有测量真实脱充电量，完整条件、参考数据和限制见 [资源评估](docs/PERFORMANCE-0.2.11.md)。用户的小红书 9.41.0 / HyperOS 4 仍需实机复测。

## 0.2.10 自动恢复与构建

- 补齐重新打开软件时的恢复入口：此前已开启监听、自动恢复开启、服务未运行时，进入页面自动恢复；手动停止和关闭自动恢复后不自行开启。
- 权限服务连接后，直到真正收到“监听已连接”才解除握手超时；连接成功后检查定时诊断心跳，30 秒清醒运行时间没有响应则清理旧连接并退避重连。深度休眠时间不计入超时。
- 丢弃已经超时的 Root Shell 异步连接回调，避免旧请求覆盖新连接。App 自身崩溃、授权拒绝等已有停止保护仍保留；系统强行停止及重启手机不会被绕过。
- 每次 main 推送或手动运行工作流，同时构建签名 Debug / Release，文件名为 `LinkIsland-版本号-Debug/Release-MD5前8位.apk`。构建成功后，两个 APK 通过一次上传进入同一 Message 消息，同时保留 GitHub Actions 产物和完整 SHA-256 校验值。

## 0.2.9 跳转与返回栈

- 修复通知跳转时把链接岛主页带到前台、从目标 App 返回后落回链接岛的问题。
- 通知入口使用独立空任务栈和透明临时页面，不与主页共用任务；转发后退出、不保留历史记录，也不进入最近任务。普通跳转、浏览器选择和授权服务跳转使用同一入口。
- 目标 App 未安装时仍询问是否改用浏览器；取消选择返回之前的 App。目标 App 内部页面的返回行为仍由目标 App 决定。
- 在 Android 16 模拟器复现旧版问题后，验证新版从外部 App 打开目标、按返回键回到来源 App；HyperOS 实机需用户复测。

## 0.2.8 大岛、后台与应用选择

- 新大岛采用官方 OS3 模板 15：左侧图标、中间名称和域名、右侧单个蓝色“打开”。不使用曾导致崩溃的 textButton 双按钮模块；旧协议保留经典兼容模板。系统负责实际尺寸和圆角，当前小米 10 未验证支持机型的真实大岛效果，按用户要求先交付测试。
- 已安装目标优先使用其应用图标；9 个常用预设补充 Simple Icons 品牌备用图标，GitHub 未安装时也有可识别图标。资源无法读取时安全退回链接图标。
- 设置新增“隐藏最近任务”：隐藏自己的最近任务卡片，可通过桌面图标返回；不隐藏监听状态通知及其中的停止入口。
- “监听自动恢复”默认开启。手动开启监听后，进程被系统回收可由 START_STICKY 恢复，授权桥断开按 2 / 5 / 10 / 30 / 60 秒退避重连，最长间隔保持 60 秒。连接等待时也能从首页停止。
- 手动停止会清除恢复意愿；授权被拒绝、监听初始化失败或 App 自身崩溃时停止恢复，避免异常循环。系统强行停止不会被绕过；重启设备后仍需手动开启监听，Shizuku 也需可用。
- 目标应用选择弹窗支持按名称或包名搜索，不区分大小写；未保存的编辑草稿不改动已有规则。
- 可选“使用授权服务跳转”（默认关闭）：在监听已连接、用户点击打开时，通过现有 Root / Shizuku 服务启动所选应用或浏览器；只允许当前绑定客户端和指定目标包，参数按独立 argv 传递，不执行剪贴板中的 shell 文本。失败回到普通跳转。
- 授权跳转用于尝试减少小米的跨应用二次确认，不提供全局关闭系统安全策略的功能。当前已验证 Root 授权路径；不同 HyperOS 的确认弹窗效果需在对应设备测试。应用锁等目标应用自己的验证不属于该开关。

## 0.2.6 异常与退出保护

- 发送前检查允许的旧版模板、必需文字、生命周期和图片 / Action 引用，禁止曾导致崩溃的 textButton 及未验证的新模板。不合格参数不交给系统，自行暂停超级岛并发送无岛扩展字段的普通通知。
- 构建或提交岛通知失败时清理旧提示，最多降级重试一次普通通知，避免重复重试异常模板。
- 正常停止监听、划掉最近任务、打开或忽略提示时统一取消通知及清理任务。没有监听时关闭测试页面所属 Activity 也清理提示；页面旋转不会触发退出清理。
- App 自身未捕获的 Java 异常会先撤销提示，保存异常状态并暂停超级岛，然后交回 Android 的崩溃处理，不自行重启进程。
- 发送前持久化提示状态，保留系统 30 秒通知超时，并另设系统 AlarmManager 清理任务。进程直接被杀死时不依赖 onDestroy；重启发现超时前仍未结束的岛提示时，先清理并暂停超级岛，可在设置手动重新开启。
- 系统清理任务为非精确闹钟，可能因省电策略延后，不把它当作严格的 30 秒保证。SystemUI 属于系统进程，App 无法捕获它的崩溃；这些措施用于阻止不合格模板发送、清理残留与防止异常恢复后再次发送。

- 展开态等宽双文字按钮暂时撤回；在支持设备完成真实渲染验证前，不将字段检查或普通通知通过视为超级岛 UI 通过。

- 规则列表、普通通知大图标与超级岛图片使用规则指定的已安装应用图标；浏览器规则使用默认浏览器图标。目标未安装或未设置默认浏览器时使用链接图标。

## 0.2.3 Root 剪贴板修复

修复 Root 进程使用 `com.android.shell` 包名读取剪贴板时，调用 UID 与包名不匹配导致系统返回空、甚至清空剪贴板的问题。读取前将特权进程主线程和读取线程的有效 UID 调整为 Shell，确保 Binder 调用身份与包名一致；Root 仍负责启动权限服务，不依赖 Shizuku。已在小米 10 / Android 15 / HyperOS 3 复现旧版问题并验证修复，Android 17 / HyperOS 4 仍需复测。

## 0.2.2 授权管理

在“设置与诊断”中新增独立授权管理页：

- 通知权限与链接提示通知：分别检查应用通知开关和提示通道，点按进入对应系统设置。通道开启不等于悬浮通知一定允许，仍需按系统设置确认。
- 取消电池优化：读取 Android 电池优化白名单状态，点按后由系统询问是否允许豁免，已允许时可进入列表管理。
- 自启动：尝试查询小米内部自启动接口，仅对明确返回的允许 / 拒绝显示结果。接口不存在、被限制或返回未知值时显示“需手动确认”；点按尝试进入小米自启动管理，失败则回到应用信息。
- 后台运行：检查 Android 标准后台限制；小米额外省电策略无法确认时显示“需手动确认”，点按尝试进入小米省电设置。
- 当前 Shizuku / Root 授权：查看服务和授权状态，点按申请或检查；只申请授权不会开启监听。Root 只在用户点按时创建权限检查会话。

打开过设置页面不代表授权成功，不提供手动勾选“已授权”的假状态。允许自启动不会自动开启监听，也不会让 App 在开机后自动启动。小米专有入口和内部接口仍需 Android 17 / HyperOS 4 真机复测。

## miuix 界面

原生 Kotlin / Jetpack Compose + miuix 0.8.8，采用选定的第二版布局。首页保留中央监听开关、状态和两个功能入口；授权方式移到“设置与诊断”。规则、测试、设置与诊断均进入独立页面。支持系统深色模式和字体缩放。原有规则与后台读取逻辑保留。

## 0.1.1 的后台读取修复

- 每 2 秒检查一次剪贴板，补偿系统未发送的复制事件；未变化的内容不会重复提示。
- 优先尝试小米带 userOperate 参数的读取接口，返回空时尝试其他已知接口。
- 同时检查各剪贴板条目的文本与网页 URI，修复只有 URI 时不触发的问题。
- 复制事件到达但读空时，在 150 / 500 毫秒后重试。
- “事件 / 检查 / 提示”计数区分系统返回空、敏感内容、非网页文本和读取异常；0.2.0 中位于“设置与诊断”。
- 新增“检查当前剪贴板”，由用户主动读取并提示已有链接，便于与后台行为对照。

若仍不触发：开始监听后从其他 App 复制公开网页链接，等 3 秒，返回链接岛，进入右上角“设置与诊断”，把运行诊断中的计数、读取结果和接口文字发回。也可以点击“检查当前剪贴板”，说明结果是否变化。**系统返回空不等于复制的链接无效**，可能是系统限制。

## 超级岛的测试边界

- 使用小米官方 `miui.focus.param`、`miui.focus.actions` 和 `miui.focus.pics`，通过 PendingIntent 执行打开 / 忽略。
- 使用官方 `canShowFocus` 查询应用权限，在“设备诊断”显示结果。
- Shizuku / Root 用于剪贴板桥接，**并不自动取得小米超级岛白名单**。
- 若显示“未允许”，普通通知仍可用于验证规则和跳转。未取得白名单或系统不兼容时，可能无法上岛。
- 本版不伪装音乐播放、不修改系统白名单、不停用或阻断小米推送服务。
- 关闭“请求小米原生超级岛”可对照测试普通通知。
- Android 17 / HyperOS 4 真机支持尚未验证。compileSdk / targetSdk 为 36，运行时适配已知剪贴板签名；系统更改内部接口时会显示初始化失败。

## 自定义规则

在 App 内添加 / 编辑 / 删除规则，第一条启用且命中的规则生效，未命中交给默认浏览器。

| 配置 | 含义 |
| --- | --- |
| 域名完全匹配 | 例如 github.com，不会匹配 github.com.evil.example |
| 包含关键词 | 忽略大小写，匹配整个 URL |
| 正则表达式 | Java 正则；支持捕获组 |
| 目标 App | 可以从已安装 App 选择，也可以输入包名；留空为浏览器 |
| 改写链接 | 留空保留原链接；域名 / 关键词规则支持 {url}；正则使用 $1 等捕获组 |

自定义 scheme 要指定目标 App；App 必须支持相应链接。不能通过规则任意打开未对外暴露的内部页面。暂不解析短链，不支持小程序口令。

## 隐私与诊断

不保存剪贴板历史。复制监听和规则匹配不联网，只转交识别到的网页链接，跳过系统标记为敏感的内容。0.2.11 增加普通 INTERNET 权限，仅在用户点击、目标小红书已安装且无法直接处理短链时，访问指定的小红书 HTTPS 域名获取重定向；不使用第三方解析服务，不记录请求链接或签名参数。通知只展示域名，完整地址仅在内存和跳转 PendingIntent 内使用。诊断只保留最后状态、监听计数和接口类型，不打印链接或异常正文。

监听启动时不弹旧链接；1 秒内完全相同的链接事件会去重，稍后再次复制仍会提示。每次复制仅处理第一条有效网页链接，最后一次提示覆盖上一条。

遇到问题，请提供以下非敏感信息：

- 所用模式（Shizuku / Root）
- “设备诊断”中的 Android API、系统构建、焦点通知协议与权限
- “设置与诊断”中的运行状态文字和计数
- 手动提示是否成功、后台复制是否触发、显示为普通通知还是超级岛、点击是否进入目标页面

不需要提供真实剪贴板、私有链接、验证码或账户凭据。

## GitHub Actions 与签名

工作流为 `.github/workflows/android.yml`。需要配置以下 Repository secrets：

| Secret | 内容 |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | PKCS12 签名文件的完整 Base64 |
| `ANDROID_KEYSTORE_PASSWORD` | 签名文件密码 |
| `ANDROID_KEY_ALIAS` | 密钥别名 |
| `ANDROID_KEY_PASSWORD` | 密钥密码 |
| `MESSAGE_PUSH_URL` | Message 服务根地址，建议 HTTPS，不是 GitHub 仓库地址 |
| `MESSAGE_PUSH_API_TOKEN` | Message 上传 API Token |
| `MESSAGE_PUSH_CHANNEL_ID` | 目标频道 ID |

Debug 和 Release 使用同一固定项目证书，凭包名区分。本地签名恢复资料保存于被 Git 忽略的 `private/LinkIsland-signing.json`，包含完整 keystore 的 Base64、别名、密码和证书指纹；文件权限为 600。请在安全位置另行备份，不要提交该文件。

本地签名构建需要设置 `LINKISLAND_KEYSTORE_FILE`（签名文件绝对路径）及三个 `ANDROID_KEYSTORE_PASSWORD` / `ANDROID_KEY_ALIAS` / `ANDROID_KEY_PASSWORD` 环境变量，然后运行 `./gradlew assembleDebug assembleRelease`。没有配置项目签名时，本地 Debug 使用 SDK 的测试签名，Release 为未签名产物；GitHub 工作流则要求完整签名配置并校验两个 APK 的签名后才发布。

Message 使用 `POST /api/upload`、Bearer Token 和 multipart 的 `channelId` / `caption` / 两个 `files` 字段。密钥不会写进源码、构建产物或日志；上传不跟随重定向。服务若使用 HTTP，Token 和附件在传输途中不会加密。
