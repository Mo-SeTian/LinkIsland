# 0.2.12 后台内存与耗电评估

测试日期：2026-10-30，Asia/Shanghai。

## 改动与约束

- Debug、Release 均启用 R8 代码裁剪及资源裁剪。Debug 保持可调试、可读名称，Release 进一步优化和混淆。显式保留两个跨进程服务的名称、构造器及 Binder 接口，避免动态服务加载失败。AGP 升至 8.13.2，以使用支持现有 Kotlin 2.3 的 R8 8.13.19，依据 [Android 工具链兼容说明](https://developer.android.com/build/releases/agp-8-13-0-release-notes)。
- 后台用不带诊断字符串的 Binder 心跳；前台按原频率获取完整诊断，恢复界面时立即获取快照。健康计时仍使用 uptime，不把深度休眠时间算成断连。
- 连接时准备剪贴板反射读取器、参数和签名；每次仍读取系统剪贴板，没有缓存链接内容代替读取。
- 保留事件即时读取、失败后 150 / 500 ms 重试、两秒兜底读取、十秒健康检查 / 三十秒失联判定，以及 2 / 5 / 10 / 30 / 60 秒重连退避。没有新增后台进程、唤醒锁、轮询计时器或周期性强制 GC。

## 内存及空闲 CPU

同一台小米 10，Android 15 / HyperOS 3，Root 模式，USB 供电、亮屏、回到桌面。先预热 15 秒，再各采样约 120 秒。对比未裁剪的 0.2.11 与裁剪后的 0.2.12 临时 Debug 包，保持旧签名、相同包名和 UID，以沿用已有 Root 授权；临时包不发布。正式交付包继续使用项目签名，Debug 带 `.debug` 后缀。

CPU 来自两个进程的 `/proc/PID/stat` 增量，单核占满为 100%；内存用 `dumpsys meminfo` 的 PSS，包含主进程和 Root 桥，避免仅看应用 UID 漏计特权进程。系统对共享页的分摊、JIT、冷热缓存和 swap 均会影响结果。

| 指标 | 0.2.11 | 0.2.12 |
| --- | ---: | ---: |
| 采样时长 | 120.07 秒 | 120.08 秒 |
| 起始合计 PSS | 130.4 MiB | 109.1 MiB |
| 结束主进程 PSS | 67.1 MiB | 53.1 MiB |
| 结束 Root 桥 PSS | 68.2 MiB | 58.9 MiB |
| 结束合计 PSS | 135.4 MiB | 112.0 MiB |
| 合计 CPU，单核口径 | 0.250% | 0.308% |
| 主进程 write_bytes 增量 | 0 | 0 |
| 配置文件 mtime 变化 | 0/24 次 | 0/24 次 |

结束时合计 PSS 约降低 17.3%。这是此设备的短时 Debug 对照，不承诺其他机型也减少固定比例；没有把 APK 缩小比例当成内存或耗电下降比例。0.2.11 上次约 132 MiB 的结果与本次约 135 MiB 的差异也说明内存会波动。

正式签名 APK 约为 Debug 7.64 MiB、Release 2.32 MiB，DEX 分别约 7.40 / 2.08 MiB。原 0.2.11 APK 约 25.9 / 20.4 MiB。日常推荐 Release，但未在本轮 Root 授权设备上测量正式 Release 的内存，不将 Debug 测量冒充 Release 测量。

## 识别速度和恢复

外部测试 App 在获得焦点后写入不同的公开 GitHub 测试链接，记录复制前 elapsedRealtime；取本应用通知的 posttimeElapsedMs，两者相减。每组五次，间隔超过重复提示保护窗口。指标包含系统通知提交，不能当成超级岛动画呈现时间。

| 场景 | 五次复制至通知提交，ms | 中位值 |
| --- | --- | ---: |
| 0.2.11 Root | 265、243、255、247、255 | 255 ms |
| 0.2.12 Root | 251、239、252、242、242 | 242 ms |
| 0.2.12 Root 主进程恢复后 | 270、242、260、253、243 | 253 ms |
| 0.2.12 Shizuku | 263、246、254、268、255 | 255 ms |

各组 5/5 识别成功，未发现此次优化增加识别延迟。两秒兜底仍保留，以上是事件路径测试，不据此宣称所有复制都必定在 300 ms 内完成。

- Root 主进程 SIGKILL 后，系统恢复前台服务并重新连接 Root 桥约 2.05 秒，恢复意愿保持；恢复后的五次新复制均成功。
- 在后台等待 35 秒，轻量心跳没有造成误重连。主动结束 Root 桥工作线程、保持 Binder 仍活着，健康检查重连完成并稳定约 39.9 秒（包含 2.5 秒稳定观察）。
- Shizuku 在后台等待 35 秒连接保持稳定；结束用户服务进程后，断线重连完成并稳定约 5.0 秒（包含 2.5 秒稳定观察）。前台重新打开时恢复监听、手动停止和关闭自动恢复三项策略回归通过。

## 耗电结论及限制

本次降低了常驻内存、反射参数分配及后台诊断字符串传输成本，周期和恢复能力保持。两段短采样 CPU 均很低，0.2.12 略高，不能据此认定 CPU 或实际耗电下降。未测量脱充每小时掉电率，也未量化唤醒次数；要判断真实省电幅度，需同一手机固定条件下做数小时脱充对照。

监听和本地规则匹配不发网络请求。仅原有的小红书短链在用户点击、目标已安装且无法直开时进行有界 HTTPS 解析。既有通知超时、备用清理及崩溃停止保护均保留。

小米 10 不支持原生超级岛，本轮不能验证 HyperOS 4 的岛动画和系统资源占用。原始采样、延迟及恢复结果位于本地忽略目录 `.tooling/perf-baseline-0.2.11-fresh.json`、`.tooling/perf-optimized-0.2.12.json`、`.tooling/latency-*.json` 和 `.tooling/main-recovery-0.2.12.json`；不包含剪贴板正文。
