# 0.2.11 资源占用与耗电评估

测试日期：2026-10-30，Asia/Shanghai。

## 结论

本次优化减少了后台诊断计数持久化和界面刷新。两分钟空闲采样中，参考版本和优化包的主进程及 Root 桥合计 CPU 分别为单核约 1.66% 和 0.25%；主进程报告的磁盘写入分别为约 1 MiB 和 0，优化包配置文件不再随两秒一次的诊断变化。新包两进程合计 PSS 约 132.4 MiB，内存仍是需要关注的常驻成本。

这是 CPU / I/O / 内存评估，不能据此给出每小时掉电百分比。手机通过 USB 供电，未做真实脱充待机电量 A/B。

## 条件和测量方法

- 小米 10，Android 15 / API 35，HyperOS 3；不是用户出问题的 Android 17 / HyperOS 4 手机。
- Root 模式，屏幕保持亮起、App 返回桌面、无新复制，先预热 15 秒，再采样约 120 秒。测试期间临时保持 USB 充电亮屏，结束后恢复原设置。
- 对比已安装的 0.2.8 参考逻辑与基于 0.2.11 改动的临时 Debug 测试包。为保持同一 UID 和已有 Root 授权，临时包沿用旧测试签名及包名；它不作为正式产物发布，正式 Debug / Release 继续使用项目签名。测试结束后停止监听并还原测试机原版本。
- `/proc/PID/stat` 的 utime + stime 增量，CLK_TCK=100；CPU 以占满一个核心为 100%。统计 App 主进程和可识别的 Root 桥进程，不把 Root 管理器算进链接岛。
- `dumpsys meminfo` 的 PSS，避免直接相加共享页较多的 RSS；同时采集主进程 `/proc/PID/io` 及配置文件 mtime。PSS 的用途见 [Android dumpsys 文档](https://developer.android.com/tools/dumpsys)。

## 实测

| 指标 | 0.2.8 参考采样 | 0.2.11 优化采样 |
| --- | ---: | ---: |
| 采样时长 | 120.07 秒 | 120.08 秒 |
| 主进程 CPU，单核口径 | 1.591% | 0.175% |
| Root 桥 CPU，单核口径 | 0.067% | 0.075% |
| 两进程合计 CPU | 1.657% | 0.250% |
| 结束时合计 PSS | 137.0 MiB | 132.4 MiB |
| 主进程逻辑写入 wchar 增量 | 355,320 字节 | 3,692 字节 |
| 主进程 write_bytes 增量 | 1,040,384 字节 | 0 字节 |
| 配置文件 mtime 变化采样数 | 24/24 | 0/24 |

优化采样结束时，主进程 PSS 约 64.3 MiB，Root 桥约 68.1 MiB。进程冷热、JIT、缓存和 swap 均影响内存值；这两段版本采样不是仅切换一个变量的严格电量 A/B，不据此宣称内存或电量按固定比例下降。

本地正式签名 APK 包体：Debug 25.9 MiB，Release 20.4 MiB。安装后还会有 ART 编译和缓存，本表不将 APK 大小当作安装后的全部占用。

## 耗电行为与边界

- 两秒兜底剪贴板检查保留，避免以增加识别延迟换取低占用；应用后台不刷新 Compose 诊断状态、不为每次计数写配置文件。
- 监听不发网络请求。仅在点击无法直接交给小红书的 HTTPS 短链时联网，限制在指定小红书域名内；用户这条短链实测为一次 302，不请求笔记正文。每次解析最多四次跳转，设置连接、读取超时及总时间预算，不使用 WebView或第三方解析服务。
- 应用代码不主动持有 WakeLock；读取的 power 记录中，含链接岛包名的锁均为系统通知提交时短暂获取后释放；这不是完整的唤醒次数或电量统计。提示本身的系统超时及备用清理闹钟继续保留。
- Root 桥使用特权进程，系统电池页可能按 shell / 特权 UID 归属，单看链接岛 UID 可能遗漏成本。因此上表同时计入两个进程。
- 真实电量还取决于 CPU 频率、休眠、显示、网络及温度等组件状态，参见 [AOSP 电源模型](https://source.android.com/docs/core/power)。要量化电量，应在同一手机脱充、固定条件下做数小时开启 / 关闭监听对照；本报告不提供未经测量的“每天耗电百分比”。

原始采样保存在本地忽略目录 `.tooling/perf-baseline-0.2.8.json` 与 `.tooling/perf-optimized-0.2.11.json`，不含剪贴板正文。
